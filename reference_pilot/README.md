# GOLDWAY — проверяемый отдельный Telegram worker

**Статус: код-кандидат, НЕ существовавший ранее пилот и НЕ запущенный Telegram-бот.**

Создан по **фактическим заголовкам** основной Google-таблицы по состоянию на 14.10.2026. Отдельный документ с предыдущими исходниками и результатами *33 тестов* не был доступен, поэтому эти тесты здесь не воспроизведены и не подтверждены.

## Функции

- Командный доступ только по заранее одобренным Telegram user ID и **только в личных чатах**.
- Задачи из `Задачи_GOLDWAY`: просмотр, статус с доказательством (менеджер).
- Ежедневный отчёт Алена: только от роли `alen`, фактические числа без автоматического заполнения; запись в `Ален_день` после проверки полей.
- Повторные касания: занесение и закрытие Аленом; напоминание по явно указанной дате в `Касания_GOLDWAY`.
- Автоматические дайджесты руководителям три раза в день по настраиваемым часам и отдельное напоминание Алену.
- Вопросы о **отправленном/полученном** — Алену. О **товарах, ещё находящихся у Насти** — Насте. По неизвестному местонахождению бот **отказывается** выбирать адресата.
- Чтение только проверенных рабочих вкладок. Запись **только** в `Задачи_GOLDWAY` (G/I), `Ален_день` (B:K), `Касания_GOLDWAY` (добавление строки / D/I). Никаких правок в `Заказы`, `Поставки`, `Склад`, `Платежи от клиентов`, финансовые формулы.
- Структурная проверка заголовков `Заказы`, `Поставки`, `Склад` без чтения сумм и без изменения ячеек; это НЕ полный финансовый/формульный аудит.
- SQLite журнал успешных напоминаний для защиты от повторов; на хостинге нужен persistent volume. Гарантированная exactly-once доставка недостижима без транзакции с Telegram; после редкого сбоя в промежутке между доставкой и журналом возможен повтор.

## Установка и локальная проверка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
pip install --no-deps -e .
pytest -q
python -m compileall -q src
```

**Не включайте продакшн только на основании unit-тестов.** После установки зависимостей и безопасной настройки доступа к Google используйте `python -m goldway.preflight` для read-only проверки таблицы. Интеграционные проверки Google/Telegram, подтверждение участников и тест доставки сообщений должны пройти отдельно.

## Безопасное подключение (без токенов в переписке)

1. Сверить **существующий** исходный архив 33-тестового пилота или приватный репозиторий с этим пакетом. Не заменять его автоматически.
2. В BotFather создать отдельного бота или выбрать существующего. Сохранить токен **только** в секретах хостинга под `TELEGRAM_BOT_TOKEN`; никогда не отправлять его в ChatGPT, файлы `.env`, таблицу, GitHub или скриншоты. Если прежний токен где-либо раскрыт — отозвать его в BotFather.
3. В Google Cloud включить Google Sheets API, создать выделенную сервисную учётную запись. Предоставить её адресу доступ к **конкретной** основной книге. Для read-only сначала Viewer, перед разрешёнными записями — Editor. Учесть, что у Editor права на всю книгу: защитить финансовые, складские, формульные диапазоны в Google Sheets и ограничить самого сервисного пользователя. Секрет JSON — в защищённых переменных Railway под `GOOGLE_SERVICE_ACCOUNT_JSON`, или защищённым файлом и путём `GOOGLE_APPLICATION_CREDENTIALS`. Google Drive connection в ChatGPT **не даёт** автоматически ключа работающему боту.
4. Настроить `GOLDWAY_MEMBERS_JSON` **в Railway Secrets**, формат `{"<telegram_numeric_id>":{"role":"admin","label":"Руководитель"}, "<id_alen>":{"role":"alen","label":"Ален"}, "<id_nastya>":{"role":"nastya","label":"Настя"}}`. Не собирать ID или токены в переписке. ID получать непосредственно в Telegram/из настроек администрирования и сверять с каждым сотрудником. Пока соответствие личности не подтверждено, не добавлять пользователя. Роли: `admin`, `manager`, `alen`, `nastya`.
5. Создать в Railway **один** persistent background worker из Dockerfile, **одну реплику** и volume с mount path `/data`. Сохранить `GOLDWAY_SQLITE_PATH=/data/notifications.sqlite3`. Для write-volume убедиться, что процесс имеет права записи (Railway mounts volumes under root; этот Dockerfile работает с default runtime user).
6. Выбрать согласованный с командой часовой пояс в `GOLDWAY_TIMEZONE` (в текущей таблице установлен `Europe/Moscow`) и согласовать время трёх проверок `GOLDWAY_DIGEST_TIMES=09:00,14:00,18:00`; это настраиваемое предложение, а не установленный пользователем график.
7. До завершения аудита держать сервис неактивным. Начать с `GOLDWAY_LIVE_ENABLED=false`, `GOLDWAY_SHEETS_WRITE_ENABLED=false`, `GOLDWAY_AUTO_SEND_ENABLED=false`. В таком состоянии worker **преднамеренно не запускает Telegram polling** и чисто завершает процесс, это контроль безопасности. После проверки всех настроек включить только `GOLDWAY_LIVE_ENABLED=true`: ручные команды проверки `/check`, `/tasks`, `/task`, `/touches` работают, но запись и рассылка выключены.
8. Каждому сотруднику необходимо первым открыть личный диалог с ботом и нажать `/start`; Telegram не позволяет боту начинать переписку с пользователем, который его не активировал. Затем проверить разрешённого и постороннего пользователя, повторяемость, неверную роль, неизвестный статус товара, пустые сроки и неопределённую оплату.
9. После теста **на копии таблицы невозможно запустить этот пакет без изменения whitelist workbook ID в коде**. Для отдельных integration tests необходимо сделать контролируемый тестовый форк и поменять ID в локальном тестовом варианте; в продакшне ID жёстко привязан к указанной книге. Перед записью в основную книгу — получить отдельное подтверждение руководителя, включить `GOLDWAY_SHEETS_WRITE_ENABLED=true` и протестировать одну из разрешённых строк. Затем разрешить `GOLDWAY_AUTO_SEND_ENABLED=true` и убедиться, что напоминания приходят один раз.
10. Наблюдать первые 48 часов: ошибки Google API, лимиты Telegram, дубль worker, хранение состояния на volume, сверка с ручными изменениями таблицы. Держать возможность немедленно отключить обе записи и уведомления, оставив чтение.

## Блокирующие условия для полноценного запуска

- СРОЧНАЯ ПРОВЕРКА ДО ВЫДАЧИ ДОСТУПА: в листе `Пользователи` есть столбец `Пароль`, при выборочной проверке 8 непустых значений. Сами значения не выписывались. Неизвестно, это хэши или открытые пароли. Доступ к книге включает возможность ЧТЕНИЯ скрытых листов и их значений. До подключения сервисной учётки проверить механизм хранения учётных данных, убрать/мигрировать секреты и при необходимости ротировать их.
- Нет исходного архива ранее заявленного Python-пилота — аудит его кода и 33 тестов не проведён.
- В `Задачи_GOLDWAY` у всех 92 задач пустой столбец H «Срок / период». Приоритетные просрочки нельзя рассчитывать до внесения подтверждённых дат ISO `YYYY-MM-DD`.
- `Касания_GOLDWAY` пока содержит только заголовки. Без записанных клиентов и дат бот не может напоминать о конкретных касаниях.
- В `Приемка_14_10` из 39 строк с товарами в 10 обнаружены текстовые отметки о требуемом сопоставлении/сверке; автоприёмка запрещена.
- В `Ален_день` на 14.10.2026 фактические поля пусты и `Отчёт заполнен=FALSE`. Бот запрашивает подтверждение, а не генерирует цифры.
- Без BotFather, разрешённых user ID, Google service-account access, Railway connection и secret store невозможен честный живой запуск.

/status 82 | К проверке | https://example.com/proof

## Важное ограничение

Этот пакет не является универсальным складским агентом: он намеренно не проводит приёмку, списание, перерасчёт веса, контроль банковских оплат или присвоение статуса «получено». Такие действия требуют отдельного подтверждённого бизнес-процесса и прав.
