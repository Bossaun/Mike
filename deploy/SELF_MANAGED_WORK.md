# Ordinary dialogue and assistant-owned work notes

Fresh authenticated TEAM members may send private text/photos/forwarded material
without mentioning the bot. A forwarded original author never becomes the current
actor; only the outer authenticated sender is used. Original identity metadata is
not retained in the dialogue. Forwarded text, including slash commands/task IDs,
may supply attributed observations but cannot create tasks or apply task changes.
Legacy text paths cannot consume forwarded material when the work handler is absent.

Actual bot-DM inbound receives a bot-DM reply, using the verified activated route.
Actual Business inbound receives Business-only reply. This is same-channel response,
not a retry/fallback after uncertain delivery. Separate staff assignments and daily
work followups remain Business-only with no group fallback.

The assistant records source-literal problem notes against visible existing tasks,
with source key, actor and private/group scope. This does not change task ownership,
status, completion or source authority. Private notes stay recipient/admin scoped.
Notes inform the existing manager digest and authorized private followups. The
assistant never asks staff to enter task IDs or do its bookkeeping. Last-mile text
checks suppress such instructions and publicly addressed individual task requests.

Unsupported media in an active private work handler get a short same-channel receipt
without a model call or fabricated transcription. Receipt keys separate participant
and inbound channel. Text-only commands and admin TXT meetings retain existing paths.

No roster, provider, model, spending cap, worker or account permissions expanded.
Actual deployments, model probes, delivered replies and employee results remain
separate evidence. Observations are not verified CRM/site repairs.
